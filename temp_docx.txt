Executive SummaryChitti Nexus is an Android application that converts scattered commitments from notifications, voice notes, images, and user-provided information into actionable tasks. It uses a privacy-first, on-device intelligence pipeline to detect deadlines, requests, payments, meetings, promises, and schedule changes without automatically sending private content to a cloud server.The project is designed to work across Android devices while using the iQOO 15 as the primary demonstration platform for hardware-aware optimization, local AI inference, camera-based capture, sensor-supported context, and performance benchmarking.2. Problem StatementImportant commitments often arrive through WhatsApp groups, SMS, email notifications, college apps, voice notes, and physical notices. These messages are quickly buried under unrelated content. Existing task and calendar applications generally depend on users manually entering every task, which is inconvenient and frequently neglected.Deadlines and assignment instructions are missed.Payment dates and reminders are forgotten.Schedule changes are not acted upon in time.Voice notes and photographed notices remain unstructured.Users must repeatedly copy information into separate productivity tools.3. Proposed SolutionChitti Nexus acts as an intelligent layer over the smartphone. It captures eligible user-approved inputs, filters irrelevant content, uses local AI to understand actionable information, validates the extracted details, and presents an action card for user confirmation.Primary workflow:Input → Lightweight Filter → Local AI Understanding → Structured Extraction → Validation → User Action4. Local AI ArchitectureStage 1: Input Capture: Android NotificationListenerService and user-triggered share/import actions.Stage 2: Lightweight Filter: Keyword matching, date patterns, language normalization, source rules, and duplicate pre-checks.Stage 3: Local Classifier: Classify whether content includes an actionable commitment.Stage 4: Structured Extraction: Extract action, date, time, location, source, category, confidence, and missing fields.Stage 5: Validation Layer: Resolve relative dates, check impossible or ambiguous times, detect duplicates, and require review when confidence is low.Stage 6: Action Card: Offer calendar entry, reminder, task creation, location association, or draft reply.Stage 7: Local Storage: Store approved task data in an encrypted or appropriately protected local database with deletion controls.7. Example User ExperiencesDeadline Detection: “Record submission tomorrow 10 AM, Lab 2.” → Chitti extracts the deadline and location, then asks whether to create a reminder.Code-Mixed Language: “25th lopu fee kattali, marchipovaddu.” → Chitti identifies a payment-related reminder and requests confirmation of the date and action.Voice Note: A user shares a voice note with assignment instructions → local transcription and extraction create a reviewable task.Image Capture: A user photographs a college notice → OCR extracts visible dates and instructions, followed by user confirmation.Location Reminder: A user associates a task with a selected college location → an opt-in geofence can surface the task when the user approaches.Daily Review: The Today screen displays pending, overdue, completed, and needs-review items, with an optional evening digest.8. Privacy, Security, and User ControlNotification access must be explicitly enabled by the user.Process only the minimum content required for the selected feature.Do not automatically send messages, accept payments, or perform sensitive actions.Require user confirmation before creating important reminders or calendar entries when extraction is uncertain.Provide clear controls for retention, deletion, and disabling individual input sources.Avoid continuous microphone, camera, or location collection unless the user explicitly starts a feature.Clearly label local processing and disclose any optional network-based functionality.9. Risks and Technical LimitationsDirect NPU access may be restricted or unavailable through public Android APIs.Hardware-specific acceleration may not work identically across Android devices.Background processing can be affected by Android power management and vendor restrictions.Notification content and structure vary between apps.Small local models may struggle with ambiguous language, sarcasm, incomplete dates, and mixed-language text.Camera, microphone, and location features require explicit permission and careful power management.The app must not claim universal hardware utilization unless each capability has been tested.14. Innovation and ScalabilityChitti Nexus is designed as an Android-first product rather than a device-locked utility. The core task engine can support different input sources and device capabilities, while hardware acceleration is treated as an optimization layer. This enables the project to scale from students to working professionals and from notifications to user-triggered multimodal capture.Android-compatible core with capability detection.Model fallback from hardware acceleration to CPU execution.Modular input connectors for notifications, images, audio, and shared text.User-controlled language and category preferences.Extensible task schema for education, work, payments, meetings, and personal commitments.Optional future integrations with supported desktop and multi-device workflows.16. Final Project PositioningChitti Nexus is a privacy-first, on-device context intelligence layer that turns scattered messages, voice notes, and captured information into actionable context. It uses the smartphone's computing capabilities to help users remember what matters, while maintaining user control over data, actions, and permissions.Core Pitch: “Chitti catches what matters, understands it on your phone, and helps you act before it gets lost.”17.
